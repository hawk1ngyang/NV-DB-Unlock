# 原理

## 1. 现象

使用 610 系列及以后的 NVIDIA 驱动时，Dynamic Boost 2.0 笔记本在 CPU + GPU 同时满载（双烤）时，显卡功耗从 Dynamic Boost 最大值被收回到基础功耗；单烤显卡仍可跑满。

## 2. 谁在决定显卡功耗上限

笔记本的 Dynamic Boost 2.0 由 NVIDIA Platform Controllers and Framework（NVPCF）实现。
驱动启动时调用 BIOS 中 NVPCF 设备（`_HID` = `NVDA0820`）的 `_DSM`（UUID `36b49710-2483-11e7-9598-0800200c9a66`），
子功能 2 返回一张动态参数表，关键字段（单位 1/8 W，即 125mW）：

| 偏移 | 字段 | 含义 |
|---|---|---|
| 0x05 | TGPA | 可配置 TGP 偏移（cTGP） |
| 0x19 | **TPPA** | **TPP 偏移：CPU+GPU 总预算 = 额定 TGP + TPP** |
| 0x1D | MAGA | Dynamic Boost 最大输出偏移 |
| 0x21 | MIGA | 最小输出偏移 |

NVIDIA 开源内核模块 `ctrl0000system.h` 中对应字段注释：
`tpp — Total processing power including CPU and GPU`，`targetTppOffsetmW — TPP, as offset in mW`。

## 3. 为什么双烤会被压

厂商 BIOS 给的 TPP 通常只有几十瓦。双烤时 CPU 功耗加上显卡功耗超过“额定 TGP + TPP”，
610 系列以后的驱动严格执行该预算，只能把显卡收回到基础功耗。

旧驱动在 NVPCF 缺失时会把显卡停在最大功耗，所以“禁用 NVPCF”曾经可以绕过限制；
新驱动在 NVPCF 缺失或与驱动不匹配时退回默认功耗，Dynamic Boost 整个失效，这个方法因此失效。

## 4. 补丁

NVPCF `_DSM` 子功能 2 中对 TPP 字段的赋值：

```asl
TPPA = <变量或常数>
```

改为：

```asl
TPPA = 0x0800   // 256W
```

使用 OpenCore 的掩码补丁，等长替换，不改变表结构：

| 补丁 | Find | Mask | Replace | 匹配 |
|---|---|---|---|---|
| 1/2 | `70 00000000 54505041` | `FF 00000000 FFFFFFFF` | `70 0B 00 08 54505041 A3` | `TPPA = <4 字母变量>` |
| 2/2 | `70 0B 0000 54505041` | `FF FF 0000 FFFFFFFF` | `70 0B 00 08 54505041` | `TPPA = <WordConst>` |

两条补丁均可重复应用（已打补丁的表再次应用结果不变）。

## 5. 安全检查

为避免误改，`0_check` 在安装前扫描所有 DSDT/SSDT，必须同时满足以下条件才判定 `COMPATIBLE`，否则安装脚本拒绝执行：

1. 存在 NVPCF 设备（`NVDA0820`）；
2. 存在 `CreateWordField(<buf>, 0x19, TPPA)`（AML `8B <buf> 0A 19 'TPPA'`），确认 TPPA 就是 NVPCF 动态参数表偏移 0x19 的 TPP 字段；
3. 整机只有**唯一一处**可匹配的 TPPA 赋值。

## 6. 为什么 TPP 取 256W

```
显卡跑满时 CPU 可用 ≈ TPP −（显卡最大功耗 − 显卡额定功耗）
```

256W（0x0800）足以覆盖笔记本 CPU 与显卡同时满载，并为驱动内部使用的额定 TGP 和实时功耗波动留出余量，
避免预算卡得太紧导致显卡被间歇性压低。TPP 只是上限，不会让任何硬件多吃电，实际功耗仍受 PL1/PL2、温度墙和适配器限制。

## 7. 为什么用 OpenCore

- Windows 的 ACPI 表覆盖（`asl /loadtable`）需要测试签名模式 → 反作弊拒绝运行。
- 刷改 BIOS → 现代平台有 Boot Guard / 厂商签名校验，不可行且危险。
- OpenCore 在 UEFI 阶段修改内存中的 ACPI 表后再引导 Windows Boot Manager，Windows 看到的是“原厂”表，无需测试签名；代价是需关闭安全启动。

OpenCore 配置为只做这两条 ACPI 补丁：不更新 SMBIOS、不写 NVRAM、不加载任何驱动或 kext、不改 ReBAR。

## 8. 注意事项

- **不要单独替换 NVPCF**：与驱动不匹配的 NVPCF 会导致 Dynamic Boost 完全失效，单烤也只有基础功耗。
- 所有脚本使用纯 ASCII 的 bat 入口 + PowerShell，避免 cmd 在 UTF-8 代码页下解析中文出错。
