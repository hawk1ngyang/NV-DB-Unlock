# 原理与分析过程

## 1. 现象

ROG Strix SCAR 16 2023（G634JZ，RTX 4080 Laptop，额定 150W，最大 175W）：

- 旧驱动：FurMark + AIDA64 双烤，显卡 175W。
- 新驱动（621.x）：双烤显卡只有 150W；单烤仍可 175W。

## 2. 谁在决定显卡功耗上限

笔记本的 Dynamic Boost（DB 2.0）由 NVIDIA Platform Controllers and Framework（NVPCF）实现。
驱动启动时调用 BIOS 中 `\_SB.NPCF` 设备（HID `NVDA0820`）的 `_DSM`（UUID `36b49710-2483-11e7-9598-0800200c9a66`），
子功能 2 返回一张动态参数表（v2.3），关键字段（单位 1/8 W，即 125mW）：

| 偏移 | 字段 | 来源变量 | 含义 |
|---|---|---|---|
| 0x05 | TGPA | ACBT | 可配置 TGP 偏移（cTGP） |
| 0x19 | **TPPA** | **ATPP** | **TPP 偏移：CPU+GPU 总预算 = 额定 TGP + TPP** |
| 0x1D | MAGA | AMAT | Dynamic Boost 最大输出偏移 |
| 0x21 | MIGA | AMIT | 最小输出偏移 |

NVIDIA 开源内核模块 `ctrl0000system.h` 中对应字段注释：
`tpp — Total processing power including CPU and GPU`，`targetTppOffsetmW — TPP, as offset in mW`。

## 3. 华硕 BIOS 给的值（DSDT 中 RCCT 方法，随奥创模式切换）

| 奥创模式 | ACBT (cTGP) | ATPP (TPP) |
|---|---|---|
| 静音 | 0 | 0xF0 = 30W |
| 性能 | 0 | 0x168 = 45W |
| 增强 Turbo | 0xC8 = 25W | 0x1B8 = 55W |
| 手动 | 0xC8 = 25W | 0x208 = 65W |

增强模式下 CPU+GPU 总预算仅为“额定 TGP + 55W”。双烤时 CPU 吃 60~90W，新驱动严格执行该预算，只能把显卡收回到 150W。

## 4. 补丁

以华硕 G634JZ 为例，位于 SSDT `OemNv2T`（NVIDIA OEM 表）中 `NPCF` 方法 sub-func#2：

```asl
TPPA = ATPP    // 70 41 54 50 50 54 50 50 41
```

改为：

```asl
TPPA = 0x0800  // 70 0B 00 08 54 50 50 41 A3   (Store WordConst, Noop 补齐长度; v1.0 为 0x0400 = 128W)
```

等长替换，不改变表结构。用 ACPICA `acpiexec` 加载整机 17 张表分别执行原版/补丁版 `_DSM`，返回的 31 字节中只有偏移 0x19-0x1A 变化（`68 01` → `00 08`，v1.0 为 `00 04`），其余完全一致。

## 5. 为什么用 OpenCore

- Windows 的 ACPI 表覆盖（`asl /loadtable`）需要测试签名模式 → 反作弊拒绝运行。
- 刷改 BIOS → 13 代 Intel Boot Guard / 华硕签名校验，不可行且危险。
- OpenCore 在 UEFI 阶段修改内存中的 ACPI 表后再引导 Windows Boot Manager，Windows 看到的是“原厂”表，无需测试签名；代价是需关闭安全启动。

## 6. 踩过的坑

- **单独换旧版 NVPCF**：旧 NVPCF 与新驱动不兼容，DB 完全失效，单烤也只有 150W（`nvidia-smi -q -d POWER` 中 Current Power Limit 恒为 Default 150W）。必须使用驱动自带的配套 NVPCF。
- **bat 中写中文**：cmd 在 UTF-8 代码页下会把多字节字符拆坏导致命令被截断，所有脚本因此改为纯 ASCII + PowerShell。

## 7. 为什么 TPP 取 256W

TPP 是“CPU+GPU 总预算”超出显卡额定功耗的部分。显卡跑到 175W 时自身已超出额定约 25W，所以：

```
显卡 175W 时 CPU 可用 ≈ TPP − 25W
```

| 目标 | 最少 TPP | 取值 |
|---|---|---|
| CPU 140W + 显卡 175W | ~165W | — |
| CPU 175W + 显卡 175W | ~200W | **256W（0x0800）** |

取 256W 的原因：驱动内部使用的“额定 TGP”无法直接读出（可能为 150W 或 125W），且实时功耗有波动，预算卡得太紧会导致显卡被间歇性压低；
同时 0x0800 在补丁字节和调试输出中一眼可辨。TPP 只是上限，不会让任何硬件多吃电，实际功耗仍受 PL1/PL2、温度墙和适配器限制。

## 8. v1.1 通用化：掩码补丁

v1.0 精确匹配华硕的 `TPPA = ATPP`。其他厂商的 BIOS 变量名可能不同，因此 v1.1 改用 OpenCore 的掩码补丁：

| 补丁 | Find | Mask | Replace | 匹配 |
|---|---|---|---|---|
| 1/2 | `70 00000000 54505041` | `FF 00000000 FFFFFFFF` | `70 0B 00 08 54505041 A3` | `TPPA = <任意 4 字母变量>` |
| 2/2 | `70 0B 0000 54505041` | `FF FF 0000 FFFFFFFF` | `70 0B 00 08 54505041` | `TPPA = <WordConst>` |

两条均为等长替换，可重复应用（已打补丁的表再次应用结果不变）。

为避免误改，`0_check` 在安装前会扫描所有 DSDT/SSDT，必须同时满足以下条件才判定 `COMPATIBLE`，否则安装脚本拒绝执行：

1. 存在 NVPCF 设备（`_HID` = `NVDA0820`）；
2. 存在 `CreateWordField(<buf>, 0x19, TPPA)`（AML `8B <buf> 0A 19 'TPPA'`），确认 TPPA 就是 NVPCF 动态参数表中偏移 0x19 的 TPP 字段；
3. 整机只有**唯一一处**可匹配的 TPPA 赋值。

在 G634JZ 的 17 张表上模拟：补丁只命中 `OemNv2T` 一处，其余 16 张表零改动，结果与 v1.0 精确补丁逐字节一致。
