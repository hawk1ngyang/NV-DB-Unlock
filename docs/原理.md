# 原理与分析过程

## 1. 现象

ROG Strix SCAR 16 2023（G634JZ，RTX 4080 Laptop，额定 150W，最大 175W）：

- 旧驱动：FurMark + AIDA64 双烤，显卡 175W。
- 新驱动（621.x）：双烤显卡只有 150W；单烤仍可 175W。

## 2. 谁在决定显卡功耗上限

笔记本的 Dynamic Boost（DB 2.0）由 NVIDIA Platform Controllers and Framework（NVPCF）实现。
驱动启动时调用 BIOS 中 `\_SB.NPCF` 设备（HID `NVDA0820`）的 `_DSM`（UUID `36b49710-2483-11e7-9598-0800200c9a66`），
子功能 2 返回一张动态参数表（v2.3），关键字段（单位 1/8 W，即 125mW）：

| 偏移 | 字段 | 来源变量 | 含义 |
|---|---|---|---|
| 0x05 | TGPA | ACBT | 可配置 TGP 偏移（cTGP） |
| 0x19 | **TPPA** | **ATPP** | **TPP 偏移：CPU+GPU 总预算 = 额定 TGP + TPP** |
| 0x1D | MAGA | AMAT | Dynamic Boost 最大输出偏移 |
| 0x21 | MIGA | AMIT | 最小输出偏移 |

NVIDIA 开源内核模块 `ctrl0000system.h` 中对应字段注释：
`tpp — Total processing power including CPU and GPU`，`targetTppOffsetmW — TPP, as offset in mW`。

## 3. 华硕 BIOS 给的值（DSDT 中 RCCT 方法，随奥创模式切换）

| 奥创模式 | ACBT (cTGP) | ATPP (TPP) |
|---|---|---|
| 静音 | 0 | 0xF0 = 30W |
| 性能 | 0 | 0x168 = 45W |
| 增强 Turbo | 0xC8 = 25W | 0x1B8 = 55W |
| 手动 | 0xC8 = 25W | 0x208 = 65W |

增强模式下 CPU+GPU 总预算仅为“额定 TGP + 55W”。双烤时 CPU 吃 60~90W，新驱动严格执行该预算，只能把显卡收回到 150W。

## 4. 补丁

位于 SSDT `OemNv2T`（NVIDIA OEM 表）中 `NPCF` 方法 sub-func#2：

```asl
TPPA = ATPP    // 70 41 54 50 50 54 50 50 41
```

改为：

```asl
TPPA = 0x0400  // 70 0B 00 04 54 50 50 41 A3   (Store WordConst, Noop 补齐长度)
```

等长替换，不改变表结构。用 ACPICA `acpiexec` 加载整机 17 张表分别执行原版/补丁版 `_DSM`，返回的 31 字节中只有偏移 0x19-0x1A 变化（`68 01` → `00 04`），其余完全一致。

## 5. 为什么用 OpenCore

- Windows 的 ACPI 表覆盖（`asl /loadtable`）需要测试签名模式 → 反作弊拒绝运行。
- 刷改 BIOS → 13 代 Intel Boot Guard / 华硕签名校验，不可行且危险。
- OpenCore 在 UEFI 阶段修改内存中的 ACPI 表后再引导 Windows Boot Manager，Windows 看到的是“原厂”表，无需测试签名；代价是需关闭安全启动。

## 6. 踩过的坑

- **单独换旧版 NVPCF**：旧 NVPCF 与新驱动不兼容，DB 完全失效，单烤也只有 150W（`nvidia-smi -q -d POWER` 中 Current Power Limit 恒为 Default 150W）。必须使用驱动自带的配套 NVPCF。
- **bat 中写中文**：cmd 在 UTF-8 代码页下会把多字节字符拆坏导致命令被截断，所有脚本因此改为纯 ASCII + PowerShell。
